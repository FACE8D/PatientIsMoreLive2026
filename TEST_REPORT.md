## Ограничения клинического содержания

- Справочные профили 17 лекарств включают фармакокинетику и ключевые ограничения по монографиям «Видаль», но не являются полными инструкциями всех производителей. Сводные перечни противопоказаний, взаимодействий и нежелательных реакций могут быть неполными.
- Для лекарственных карточек ссылки ГРЛС ведут на фильтрованный поиск по МНН, если конкретная запись не подтверждена. Врач должен выбрать точного производителя, форму, дозировку и действующую регистрацию.
- Для «Авиандра®» добавлена отдельная страница препарата в «Видаль» и отдельная монография действующего вещества. Для флуоксетина используется монография действующего вещества; старая продуктовая страница содержит истёкший срок регистрации и не считается подтверждением текущей регистрации.
- В российском стандарте для флуоксетина единица напечатана как «мл». Приложение сохраняет значение из источника и выделяет необходимость проверки, не исправляя его предположением.
- Никакая лекарственная карточка и сравнение не заменяют проверку актуальной инструкции выбранного продукта и клиническое решение врача.
- Не проведены клиническая валидация, экспертиза лицензий, правовая проверка статуса всех источников, независимый аудит безопасности и проверка совместимости с конкретной PACS/системой электронных медицинских карт.
- Не проверены фактическая доставка Web Push/FCM и работа подписанного APK: требуется собственная конфигурация VAPID/Firebase и Android SDK/credentials.

## Исправления переключения пациента, календаря и сообщений — 2026-10-25

- В `loadPatient()` больше не добавляется текущая карточка в `directoryRows`: эта ошибка заменяла страницу списка пациентов открытой карточкой и после переключения оставляла в шапке только последнего выбранного пациента. Теперь источник списка остаётся неизменным до загрузки следующей страницы; текущая карточка добавляется в варианты выбора отдельно.
- Добавлены недостающие обработчики кнопок `Удалить событие`, `Изменить сообщение`, `Удалить сообщение` и `История правок`. Визуально отрисованная кнопка теперь вызывает соответствующий API.
- Запланированное календарное событие удаляется мягко (статус `deleted`), журналируется, а пациент при удалении врачом получает внутреннее уведомление. Завершённые, пропущенные, перенесённые и системные события изменения терапии нельзя удалить как обычный слот.
- Сообщение можно редактировать или удалить только отправителю. При редактировании сохраняется предыдущий и новый текст, причина и автор; при удалении тело не очищается из защищённой базы, а в обычной переписке показывается заглушка. Врач может открыть историю правок; исходный текст не показывается в обычном API после удаления.

- Причина: общий CSS-селектор `.form-field input` задавал `width: 100%` также флажкам симптомов, из-за чего флажок занимал всю ячейку и выталкивал подпись.

- Регрессионная браузерная проверка измеряет ширину флажков и границы подписей для всех симптомов на широком экране, экране телефона и в режиме для слабовидящих; также проверено переключение флажка.
