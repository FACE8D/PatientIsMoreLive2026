## Схема JSON

Верхний уровень включает `id`, `title`, `category`, `respondent` (`patient` или `clinician`), `instruction`, `source`, `version`, `questions`, `scoring`, `license_review_required`, `implementation_notes`.

У вопроса обычно есть `id`, `text`, `type`, `options` (каждый option: `value`, `label`), `required`, `scored`, и необязательные поля `section`, `help`, `scoring_group`, `periods`. Для специальных типов следуйте уже имеющимся JSON и серверному коду.

## Обязательные проверки для новой версии

1. Права/лицензия и разрешённость цифрового воспроизведения подтверждены документально.
2. Формулировки, порядок и значения ответов сверены с конкретной валидированной русскоязычной версией.
3. Алгоритм расчёта подтверждён тестами на минимум, максимум, пропуски, обратные вопросы и граничные значения.
4. Источник, версия, дата ревизии и необходимые ограничения внесены в JSON.
5. Новая версия не подменяет исторически заполненную без идентификатора версии.
6. Не добавляйте самодельную диагностическую интерпретацию. Скрининг не тождествен диагнозу.

`license_review_required: true` означает, что требуется проверка, а не наличие лицензии. Пакет предназначен для разработки и тестирования; он не подтверждает право дальнейшего распространения оригинальных формулировок и не заменяет профессиональную интерпретацию.
